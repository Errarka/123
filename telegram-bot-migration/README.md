# Перенос Telegram-бота на другой сервер

Эти скрипты нужно запускать **не отсюда** (эта сессия Claude Code работает в
песочнице без исходящего SSH), а с любой машины, у которой есть обычный
доступ в интернет по SSH — ваш ноутбук/ПК, промежуточный сервер и т.п.

## Требования на машине, где вы запускаете скрипты

- `ssh`, `rsync`
- `sshpass` — только если хотите использовать пароль, а не SSH-ключ
  (`apt install sshpass` / `brew install sshpass`)

## Шаг 1. Найти бота на исходном сервере

```bash
SRC_HOST=147.78.65.84 SRC_USER=root SRC_PASS='пароль_от_старого_сервера' \
  ./discover.sh
```

Скрипт **ничего не меняет**, только смотрит: запущенные процессы,
systemd-сервисы, cron, pm2/screen/tmux-сессии, docker-контейнеры и файлы,
похожие на исходники Telegram-бота (по упоминанию токена или библиотек
типа `aiogram`, `python-telegram-bot`, `node-telegram-bot-api`, `telegraf`
и т.д.).

Из вывода выпишите:
- путь к папке с ботом (например `/root/my_bot`)
- как он был запущен (имя systemd-сервиса / pm2-процесса / команда в cron)

## Шаг 2. Перенести бота на новый сервер

```bash
SRC_HOST=147.78.65.84 SRC_USER=root SRC_PASS='пароль_от_старого_сервера' \
DST_HOST=91.186.223.150 DST_USER=root DST_PASS='пароль_от_нового_сервера' \
BOT_DIR=/root/my_bot \
  ./migrate.sh
```

Скрипт сделает по порядку:

1. Скопирует папку `BOT_DIR` со старого сервера на новый (по тому же пути),
   исключив `venv`, `node_modules`, `__pycache__`, `.git`.
2. Определит тип проекта (Python по `requirements.txt` или Node.js по
   `package.json`) и установит зависимости уже на новом сервере.
3. Спросит команду запуска (например `venv/bin/python3 bot.py` или
   `node index.js`) и создаст на новом сервере systemd-сервис с
   автозапуском и перезапуском при падении.
4. Запустит сервис и покажет логи, чтобы можно было убедиться, что бот
   поднялся и не падает с ошибкой (неверный токен, не хватает зависимости
   и т.п.).
5. Спросит, остановить ли бота на старом сервере. **Важно**: если бот
   работает через long polling (`getUpdates`), он не может одновременно
   работать на двух серверах — начнутся ошибки `409 Conflict` и часть
   сообщений будет теряться. Сначала убедитесь, что новый бот отвечает в
   Telegram, и только потом останавливайте старый.

## После переноса

- Проверьте бота в Telegram (напишите ему `/start` или любую команду).
- Проверьте, что файл с секретами (`.env`, токен) скопировался и не попал
  в `.gitignore`/исключения — скрипт копирует всё содержимое `BOT_DIR`,
  кроме `venv`/`node_modules`/`__pycache__`/`.git`.
- Смените пароли root на обоих серверах — они были переданы открытым
  текстом в переписке.
- Если у бота есть база данных (SQLite-файл, PostgreSQL и т.д.) вне
  `BOT_DIR` — её нужно перенести отдельно (для SQLite достаточно
  скопировать файл вместе с `BOT_DIR` или добавить в `rsync`, для
  PostgreSQL/MySQL — сделать дамп на старом сервере и восстановить на
  новом: `pg_dump` / `mysqldump` + импорт).

## Если что-то пошло не так

- Логи нового сервиса: `journalctl -u <имя-сервиса> -n 100 --no-pager`
  на **новом** сервере.
- Откатиться: просто не останавливайте (или снова запустите) бота на
  старом сервере — рабочая копия там осталась нетронутой.
